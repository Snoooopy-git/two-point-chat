# 双点聊天架构

## 系统概览

双点聊天是 Vue 3、Express 5、Socket.io 和 SQLite 组成的单实例聊天应用。

| 层 | 技术 | 责任 |
|---|---|---|
| Web | Vue 3、Pinia、Vue Router、Vite | 登录、联系人、聊天、管理员界面 |
| HTTP | Express 5 | 认证、好友申请、好友、消息、上传和管理 API |
| 实时 | Socket.io 4 | 私聊、在线状态、输入状态和已读事件 |
| 数据 | better-sqlite3、SQLite WAL | 用户、好友关系和消息 |
| 入口 | Nginx、PM2 fork | TLS 终止、反向代理和单进程管理 |

## 运行时边界

- Express 只监听回环地址，由 Nginx 对外服务。
- PM2 必须保持单实例 fork 模式；不得在未重新设计在线状态和 SQLite 写入模型前启用 cluster。
- 生产数据目录必须与代码目录物理分离。数据库通过 `CHAT_DB_PATH` 指定，上传目录通过 `CHAT_UPLOAD_PATH` 指定。
- 数据库、WAL/SHM、上传、日志、备份和 `.env` 不得进入 Git 或发布包。
- 生产配置由环境变量提供，仓库只保存无密钥模板。

## 请求与消息路径

1. 用户通过 HTTP 登录并获得短期 JWT。
2. HTTP API 通过认证中间件校验令牌及账号状态。
3. Socket 握手使用同一 JWT，并应用同等账号状态规则。
4. 消息先持久化到 SQLite，再向接收方发送事件，最后向发送方确认。
5. 客户端收到确认后，用稳定的客户端消息 ID 替换乐观消息。
6. `clientMessageId` 在单个发送者范围内唯一；断线重试复用该值，数据库唯一索引保证消息幂等。
7. Socket 连接后先接收好友在线快照，再以增量事件维护在线状态。
8. 历史消息按消息 ID 游标从最新页向前加载，单页最多 200 条。
9. 添加好友先写入单向待处理申请；接收方接受后，事务内写入双向好友关系并删除待处理申请。

## 工作区与桌面宠物

- 桌面工作区由联系人、主内容和工具栏三列组成；中等屏幕使用侧滑工具栏，移动端使用全屏工具面板。
- 工具栏中的日历完全运行在客户端本地时区，不保存日程或向服务端写入数据。
- “跳跳信使”使用 4×2 PNG 图集逐帧播放；动作资源由 Vite 管理，原始生成包不作为运行时资源直接加载。
- 宠物状态由本地交互、消息到达和输入状态驱动，不改变消息协议；拖动位置仅限工具栏内部。
- 系统启用减少动态效果时，宠物停止自动行走和逐帧动画。

## Web Component 约束

- Vite Vue 编译器必须用 `isCustomElement` 声明 Web Component。
- 事件使用 `@event-name` 模板绑定，禁止用挂载后的手工监听代替。
- 组件首次初始化必须可见，避免依赖布局测量的组件得到错误尺寸。

## 数据库约束

- WAL、foreign keys 必须启用。
- 迁移失败必须阻止服务启动，不能静默忽略。
- 新查询应评估索引、分页、稳定排序和最坏数据量。
- 删除、清理、好友双向写入等多语句操作必须使用事务。
- `friend_requests` 仅保存待处理申请；接受、拒绝或取消后删除，现有 `friendships` 只表示已确认关系。
- 消息客户端 ID 使用部分唯一索引，旧消息的空值保持兼容。
- 所有时间必须明确时区，API 推荐输出 ISO 8601 UTC。

## 支持环境

- 本地开发：Windows PowerShell、Node.js 20.19+。
- 生产：Alibaba Cloud Linux 3、Node.js 20.19+、Nginx、PM2 fork。
- CI：Linux、Node.js 20.19+。
- 原生依赖不得跨 Windows/Linux 复制，目标环境必须重新安装或重建。
