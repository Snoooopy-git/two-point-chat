# 测试与交付证据

## 统一门禁

```bash
npm run check
```

该命令依次执行治理检查、静态检查、自动化测试和前端生产构建。安全、认证、数据库、部署或公共配置变更必须执行完整门禁。

## 影响面测试矩阵

| 变更类型 | 最小验证 | 追加验证 |
|---|---|---|
| 文档 | 治理检查、链接和命令人工核对 | 涉及运维命令时执行语法检查 |
| Vue 组件 | lint、构建、相关组件/浏览器路径 | 响应式布局、键盘和异常状态 |
| HTTP API | lint、单元/集成测试 | 认证失败、越权、非法输入、数据库失败 |
| Socket | 双客户端集成测试 | 断线重连、多标签、禁用账号、重复事件 |
| SQLite | 临时数据库测试 | 迁移、事务、备份、恢复、完整性检查 |
| 安全配置 | 完整门禁 | 缺失配置、弱配置、密钥泄漏扫描 |
| 部署 | 完整门禁、shell 语法检查 | staging 冒烟、备份恢复、失败回退 |

## 本地烟雾测试

- 使用系统临时目录中的数据库，禁止写入仓库数据库。
- 启动到随机可用端口，验证 `/api/health`。
- 前端构建后验证首页返回 HTML。
- 测试结束必须关闭服务并删除临时目录。
- Socket 回归必须验证在线快照、禁用后会话撤销、重复 `clientMessageId`
  不重复投递和数据库唯一性。
- 好友回归必须验证申请幂等、反向申请冲突、处理权限、接受后的双向关系，以及拒绝/取消不创建好友关系。
- 工具栏回归必须覆盖三栏、侧滑和移动端布局；日历验证周一起始、跨月和闰年；宠物验证点击、拖动边界、消息触发、定时器释放及减少动态效果。
- 消息回归必须验证最新 200 条、游标前翻、软删除摘要过滤和已读持久化。
- 上传回归必须使用系统临时上传目录，分别验证真实签名、伪造 MIME、安全文件名和响应头。

## 交付证据

交付报告至少包含：

1. 确认范围与明确排除项；
2. 实际变更文件；
3. `npm run check` 结果；
4. 额外测试及其结果；
5. `git diff --check` 与最终工作区状态；
6. 未验证项、原因和剩余风险；
7. 若创建版本，记录 commit 和 tag；若未 push，明确说明。

## 失败处理

- 同一根因连续两次修复仍失败时停止试错。
- 环境问题必须保留原始错误和复现命令。
- 不得通过删除测试、降低断言、关闭 lint 规则或吞掉异常来获得通过结果。
