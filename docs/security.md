# 安全基线

## 密钥与配置

- 生产 `JWT_SECRET` 只能来自运行环境或密钥管理系统。
- 密钥长度不得少于 32 个字符，且不得包含明显占位词。
- `.env`、私钥、令牌、数据库、日志和备份禁止进入 Git。
- CI 必须运行依赖审计、CodeQL 和仓库治理检查。

## 认证与权限

- HTTP 和 Socket 必须采用一致的令牌、用户存在性和账号状态校验。
- 禁用、删除或降权应在明确的最大延迟内生效。
- 管理员创建必须使用受控的运维流程，禁止依赖可抢注用户名。
- 权限判断必须使用数据库当前状态，不得信任客户端角色。
- 登录和敏感操作应记录不含凭据的安全审计事件。

首次管理员引导必须先备份数据库，再经过 L2 确认执行：

```bash
npm run admin:promote -- --database <db> --username <user> --confirm <user>
```

命令只允许提升已存在且处于 active 状态的用户。

## 输入与资源限制

- 所有外部输入必须验证类型、长度、枚举和关联资源权限。
- 登录、注册、搜索、上传及 Socket 高频事件必须限流。
- 上传文件必须校验真实文件签名，重新生成文件名与扩展名，并设置安全响应头。
- 禁止仅依赖浏览器 `accept` 或请求声明的 MIME 类型。

## Web 与传输

- 生产必须使用 HTTPS，并将 HTTP 重定向到 HTTPS。
- 设置 CSP、`X-Content-Type-Options: nosniff`、Referrer-Policy 等安全头。
- CORS 使用明确允许列表；同源部署不应开启不必要的跨域访问。
- 前端不得使用 `v-html` 渲染不可信内容；令牌存储策略需纳入 XSS 风险评估。

## 数据保护

- 数据库、上传和备份目录采用最小权限。
- 备份必须加密或处于受控存储，并设置保留与销毁策略。
- 日志禁止记录密码、JWT、完整消息正文和其他敏感信息。
- 至少每季度执行一次恢复演练，并记录恢复时间、完整性结果和发现的问题。

## 安全问题处理

发现已泄露密钥时，代码修复不等于风险解除。必须轮换密钥、使旧令牌失效、检查访问日志，并记录事故影响范围。
