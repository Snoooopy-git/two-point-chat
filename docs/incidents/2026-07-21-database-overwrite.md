# v0.1.2 生产数据库覆盖事故复盘

日期：2026-07-21

## 影响

部署包包含本地 `server/chat.db*`，解包时覆盖生产数据库；部署前没有一致性备份，生产用户数据无法从该流程恢复。

## 独立根因

1. 发布包未排除 SQLite 数据文件。
2. 部署前没有数据库备份。
3. 部署后只验证 HTTP，没有验证数据完整性。
4. 使用全量 tarball 覆盖代码目录。
5. 环境数据与代码没有物理分离。
6. 部署依赖人工记忆，没有自动门禁。

## 永久措施

- 数据库、上传、日志和备份移出代码目录。
- 发布只允许使用已确认 tag 或受控增量同步。
- SQLite WAL 模式使用在线备份 API，不复制 Windows 构建产物或活动 WAL 文件。
- 部署前验证备份，部署后验证关键数据和 API。
- CI 检查 Git 中不得出现数据库、上传或生产配置。
- 定期执行恢复演练，证明备份可以实际恢复。

## 回退原则

代码回退和数据恢复必须分开处理。代码可切换到已确认 tag；数据恢复必须重新确认备份时间点、目标路径和可接受的数据损失窗口。
